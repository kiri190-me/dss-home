# dss-home — (주)디에스에스 회사 홈페이지

기존 `dss21.com`(그누보드)을 대신할 회사 소개 사이트다. 손님이 보는 공개
사이트이고, 오른쪽 위 **[사내 시스템]** 버튼이 직원용 통합 로그인 포털로
연결된다.

## 세 프로젝트의 관계

| | 폴더 | 포트 | 역할 |
|---|---|---|---|
| **회사 홈페이지** | `dss-home` | 3200 | 공개. 여기 |
| 로그인 포털 | `dss-auth` | 3100 | 신원 확인, 통행증 발급 |
| A/S 관리 시스템 | `RF_Service_System` | 3000 | 통행증을 받아 쓰는 시스템 |

홈페이지를 포털 안에 넣지 않고 따로 둔 이유: 회사 소개 문구를 고치는 일이
통행증을 발급하는 보안 핵심 코드를 건드리지 않게 하기 위해서다.

## 띄우기

```
npm run work:start   # Docker·DB·주소를 점검한 뒤 3200 + 포털(3100)
npm run dev          # 홈페이지만 (3200)
```

[사내 시스템] 버튼을 눌러 실제로 로그인까지 보려면 `dss-auth`도 함께 떠
있어야 한다. `work:start`가 그것까지 켜 준다 — 바탕화면 '작업 시작' 메뉴의
**5. 회사 홈페이지**가 부르는 것과 같은 스크립트다(`scripts/start-home-work.ps1`).

끌 때는 `npm run work:end`. 커밋하지 않은 것이 있으면 끄지 않고 멈춘다
(알고도 끄려면 `npm run work:end -- -Force`). 바탕화면 '작업 종료'는 네
시스템을 한꺼번에 끄면서 이 스크립트도 함께 부른다.

수리 의뢰를 사내가 당겨가는 길(`/api/nas-sync/*`)까지 확인하려면 A/S 시스템도
떠 있어야 한다 — '작업 시작' 메뉴의 **0. 전부 한 번에**가 넷을 모두 켠다.

⚠️ **Turbopack을 쓰지 않는다.** 이 개발 PC의 Application Control 정책이 Next의
네이티브 SWC 바이너리를 차단한다. 오류 문구는 플랫폼 문제처럼 보이지만 원인은
보안 정책이다. `dev`·`build` 스크립트에 `--webpack`이 이미 들어 있다.

## 설정

`.env.local` (예시는 `.env.example`):

| 이름 | 뜻 |
|---|---|
| `PORTAL_URL` | [사내 시스템] 버튼이 향하는 주소. 기본 `http://localhost:3100` |

`NEXT_PUBLIC_` 접두사가 없으므로 이미지를 다시 빌드하지 않고 환경변수만 바꿔도
반영된다.

> ## 이 사이트는 사내 NAS에 올리지 않는다 (2026-09-02 확정)
>
> **앱도 DB도 회사 밖 호스팅에 둔다.** 나머지 세 시스템(포털·A/S·계측기)만
> Synology NAS로 옮긴다.
>
> 손님이 보는 공개 사이트이기 때문이다. 사내 NAS에 두면 외부 공개를 위해
> 방화벽에 구멍을 내야 하고, **그 구멍이 포털·A/S·계측기 옆에 뚫린다.**
> 사내 전용 원칙을 지키는 가장 확실한 방법은 공개돼야 하는 것을 애초에 같은
> 상자에 넣지 않는 것이다.
>
> **그래서 이렇게 된다**
>
> - `PORTAL_URL`이 가리키는 사내 포털은 **사내망에서만 닿는다.** 밖에서 이
>   사이트를 보는 손님이 [사내 시스템] 버튼을 눌러도 들어가지 못한다 —
>   그게 맞다. 사원이 밖에서 쓰려면 VPN으로 사내망에 들어와야 한다.
>   **이걸 "고치려고" 포털을 인터넷에 열지 말 것.**
> - 사내 A/S가 이 사이트의 `/api/nas-sync/*`를 **불러 간다**(`DSS_HOME_URL`로
>   나가는 요청). 방향이 안에서 밖이라 **방화벽에 구멍이 필요 없다.**
>   인증은 `DSS_HOME_SYNC_SECRET`이 맡는다.
> - `docker-compose.yml`은 개발용일 뿐이다. 운영 DB는 호스팅이 주는 것을 쓴다.
>
> 근거는 `../dss-deploy/runbook/01-postgres-통합.md` 4절.

## 알아 둘 것

- **원본 사진을 가져오지 않았다.** 배너의 세계지도 사진(1.8MB)은 출처가
  적혀 있지 않은 스톡 이미지다. 라이선스를 확인할 수 없는 파일을 새 저장소로
  옮기는 대신, 같은 인상을 CSS와 SVG로 다시 그렸다. 회사가 원본과 사용 권리를
  갖고 있다면 `page.tsx`의 `<HeroBackdrop />`만 갈아 끼우면 된다.
- **로고는 SVG로 그린다.** 표식(파랑·흰색·빨강 정사각형 셋)의 치수는
  `dss-auth`의 `DssLogo.tsx` 및 `scripts/generate-icons.ts`와 같은 값이다.
  한쪽을 고치면 다른 쪽도 고쳐야 두 사이트가 같은 회사로 보인다.
- **제품 설명은 임시다.** 원본 게시판이 비어 있어 제품군 이름에서 벗어나지
  않는 선까지만 적었다. 실제 사양과 용도는 담당자가 채워야 한다.
- **다크 모드를 두지 않는다.** 회사 소개 사이트는 인쇄물·명함과 같은 얼굴이라
  보는 사람의 OS 설정에 따라 색이 달라지면 안 된다. 원본도 밝은 화면 하나뿐이다.
